# MEDIAN v0.5.0 — UI Mockup Manifest

Status: derived Sourcebook production manifest

Basis: approved entries in `M050_Sourcebook_Augments_Working_Plan.md`

Authority: noncanonical. This manifest inventories the interface presentations
required by the approved Augments map. The GDD and Augments plan govern the
game and the pages; this file creates no additional interface canon.

## Purpose

The Sourcebook describes a theoretical computer game. Its UI mockups therefore
need to make the game imaginable and its rules legible without pretending to
be implementation-ready software specifications. Every mockup is a particular
worked state of the world, not a generic wireframe filled with placeholder
content.

The production burden falls into three classes:

1. **Primary presentation** — a complete or dominant current-spec game view
   that must be composed as its own asset.
2. **Derivative state** — a changed Round, inset, crop, annotation layer, or
   reduced state built from an approved primary presentation.
3. **Editorial assembly** — a Sourcebook diagram or atlas that uses exact UI
   fragments but commissions no additional complete interface.

Generated imagery may provide environmental and character backplates. Names,
rules, options, labels, arrows, callouts, and all other semantic content remain
editable production elements. Canon Citizen and Colony imagery is mandatory
reference wherever a named subject appears.

## Shared production rules

- Scene and situated bodies remain primary. Interface architecture frames the
  world rather than shrinking it into an optional illustration window.
- Mockups show only information legitimately available in the represented
  state. Hidden Exposure, probabilities, backend authority, and unresolved
  consequences remain hidden unless a Sourcebook-only annotation explicitly
  identifies them as editorial information.
- Inactive options remain visible in their established order and are greyed
  with a concise situated reason when that grammar applies.
- Citizens appear in the scene wherever the Register permits. Permanent
  portrait strips, Health/Spirit meters, Unity bars, success percentages,
  mission scores, advisor ribbons, and inherited v0.4 interface furniture do
  not survive merely because they occur in a useful legacy composition.
- The exact same Citizen, Colony, Node, Item, and terrain references persist
  across linked presentations. Later states amend earlier ones; they do not
  silently recast them.
- Each composed page must remain intelligible in a single-page landscape PDF
  viewed in vertical scroll. No mockup depends upon a facing page.

## Micro-briefs not yet owned by a primary augment

Three small interface subjects are required only as exact fragments inside
later editorial pages. They should be briefed at fragment scale and must not
grow into additional full-page mockups:

1. **Almanac current-state fragment** — use Rushbottom immediately before or
   after Grand Manor Recognition so it coordinates with `AUG-6.1-01` and
   UI-15. It presents current and prospective information, never memory.
2. **Map fragment** — use the same known Corridor state as the Part V
   expedition or Chapter 6.4 campaign map. It displays known ground and
   persistent places without drawing prescribed routes.
3. **Citizen view fragment** — use the Citizen selected for `AUG-7.2-03` and
   expose only established identity, current state, relationships, Role,
   Residence, Items, and Tale access appropriate to that view.

Storehouse also requires one small visual-system brief: a visible DWELL
Practice whose selection opens the Resources screen. That screen is always
menu-accessible, but the physical Storehouse supplies the in-world hook. The
Open Table is not part of this brief; it is a Gathering Place improvement and
a large-cast observational Presence eligibility condition.

## Production order

1. **Lock the shared grammars:** UI-01 MEET, UI-02 DWELL, UI-04 EMBODY, UI-06
   TRAVEL, and the three RISK interfaces.
2. **Build the continuous expedition:** UI-05, UI-10, its Round-two
   derivative, UI-12, UI-13, and UI-14 against one exact accounting state.
3. **Build bounded special states:** UI-03, UI-11, UI-16, UI-17, and UI-18.
4. **Build memory presentation:** UI-15 and the Almanac/Map/Citizen
   micro-briefs.
5. **Assemble derivatives:** Part VI and VII comparisons, annotations, sound,
   authoring diagrams, and Appendix G only after their primary assets are
   stable.

This order is dependency-based rather than book order. It minimizes duplicate
composition and lets the same canon-grounded imagery carry a life, place, and
world consistently through several pages.

## Completion test

The mockup set is ready for page production when:

- every primary entry has one exact authored state and a bounded asset brief;
- the five Registers are each legible through at least one complete worked
  presentation;
- only RISK receives three complete Core-Species variants;
- linked expedition, Citizen, Colony, Item, Node, and landscape facts persist
  without recasting;
- all semantic text remains editable and current;
- each derivative points to a primary asset rather than silently commissioning
  another interface family; and
- the resulting pages make a coherent theoretical game visible without
  claiming to be a shipping UI specification.
